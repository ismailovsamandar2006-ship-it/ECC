# BANK BATTLE LIVE — версия для Vercel

**Готовая многопользовательская игра по цифровому банковскому делу** на основе всех шести предоставленных учебных файлов.

- 3 команды, автоматическое равномерное распределение участников;
- 5 раундов по 6 вопросов = **30 вопросов**;
- смартфоны студентов: QR-код → имя → команда → ответы;
- экран ведущего с управлением; отдельный публичный экран проектора 16:9;
- звуки, абсолютный серверный таймер, золотые вопросы ×2, финальные риск-ставки 50/100/200;
- онлайн-голосование с фиксацией **одного** ответа на игрока;
- командное табло, список участников, статистика ответов, пьедестал победителей;
- сохранение комнат между обновлениями страниц; повторное подключение с того же смартфона по сохранённому токену.

## Vercel: проект и база данных

Игра развёрнута как Vercel-проект **`bank-battle-live`** (команда `dojo`):

- сайт для студентов и ведущего: **<https://bank-battle-live.vercel.app>**
- пульт ведущего: <https://bank-battle-live.vercel.app/host.html>
- проверка сервера: <https://bank-battle-live.vercel.app/api/game?op=health>

Статические страницы отдаются из `public/`, серверная логика — функции `api/game.js` и `api/qr.js`. В настройках проекта Vercel **Root Directory = `apps/bank-battle-live`**: сборка идёт из этой папки репозитория.

Vercel запускает код как отдельные функции, поэтому общий счёт хранится в **Upstash Redis** (REST по HTTPS, опрос раз в 1.3–3.2 секунды). Без базы главная страница покажет предупреждение «Требуется подключить Upstash Redis», а создание комнаты вернёт понятную ошибку конфигурации.

### 1. Подключить Redis (один раз, ~1 минута)

1. Vercel → проект **bank-battle-live** → вкладка **Storage** → **Create Database** → **Upstash for Redis** (бесплатный план подходит).
2. Регион базы — **Frankfurt (eu-central-1)**: там же работают функции игры. Подключите базу к проекту для окружений **Production** и **Preview**.
3. Vercel сам добавит переменные `KV_REST_API_URL` и `KV_REST_API_TOKEN` (или с вашим префиксом, например `STORAGE_REST_API_URL`) — игра находит их автоматически.
4. Сделайте **Redeploy** последнего деплоя (Deployments → ⋯ → Redeploy), чтобы функции получили переменные.

Если база создана вручную на [Upstash](https://console.upstash.com/), добавьте в Vercel → **Settings → Environment Variables** пару `UPSTASH_REDIS_REST_URL` и `UPSTASH_REDIS_REST_TOKEN` (обычный, не read-only токен) и тоже выполните Redeploy. Не публикуйте токен в чате, GitHub или HTML.

### 2. Обновить сайт после изменений

- Новые переменные окружения (например, после подключения Redis): Vercel → **Deployments** → последний деплой → ⋯ → **Redeploy**.
- Новые правки кода: запустите `npx vercel --prod` **из корня репозитория** (при первом запуске выберите существующий проект `bank-battle-live`) или `DEPLOY_VERCEL_WINDOWS.bat` на Windows — он сам перейдёт в корень. Vercel возьмёт Root Directory `apps/bank-battle-live` из настроек проекта; запуск прямо из этой папки завершится ошибкой «path does not exist».

### 3. Проверить, что онлайн-игра работает

1. Откройте `https://<домен>/api/game?op=health` — ожидается `"configured": true`, `"questions": 30` и отпечаток банка вопросов `"bank"` (меняется при каждой правке `lib/questions.js`, так можно убедиться, что задеплоена нужная версия).
2. Откройте `/host.html`, нажмите **Создать комнату**.
3. Откройте **Экран проектора** (отдельная вкладка) и выведите его на большой экран (`F11`).
4. Отсканируйте QR-код **с трёх разных телефонов**: каждый автоматически попадёт в свою команду.
5. Запустите игру с пульта, ответьте со всех телефонов и проверьте табло после «Показать ответ».

Студентам давайте только **production-домен** проекта (`*.vercel.app` из вкладки Domains). Уникальные адреса отдельных деплоев и Preview закрыты Vercel Authentication и на телефонах студентов не откроются.

### Режим локального тестирования

Для тестирования без Upstash (только пока работает один компьютер):

```bash
npm run dev
```

Откройте `http://localhost:3000`; для телефонов в **одной Wi-Fi-сети** используйте показанный в консоли адрес `http://192.168.x.x:3000`. На Windows можно запустить `START_LOCAL_WINDOWS.bat`. Локальная память очищается при перезапуске и не подходит для Vercel/продакшна. Команда `npm run check` запускает автоматические проверки сервера.

## Как считать очки

Чтобы соревнование было справедливым при неодинаковом числе студентов в командах, каждый вопрос приносит команде **среднее количество очков её участников**, а не сумму. Например, если трое набрали 150, 100 и 0, команда получит 83 очка.

- Раунды 1–4: за верный ответ базовые 100 / 120 / 130 / 140 очков плюс до 50 бонусных за скорость (чем быстрее, тем больше); золотые вопросы удваивают результат. Неверный / пропущенный ответ — 0.
- Раунд 5: каждый заранее выбирает ставку 50, 100 или 200; верно +ставка, неверно −ставка, без ответа 0. Скорость здесь не учитывается.
- Сервер рассчитывает баллы и фиксирует результаты **только при закрытии вопроса ведущим**. Табло участников и команд обновляется у всех.
- Равенство финальных очков отображается как ничья.

## Защита и надёжность

- Секреты базы лежат только в серверных переменных и не отправляются студентам.
- Отдельный секретный токен ведущего (хранится в браузере ведущего); участникам не доступны команды управления.
- Для каждого студента создаётся собственный токен, сохраняемый в его браузере, — перезагрузка страницы не создаёт нового игрока.
- Ответ на вопрос можно отправить только один раз и только до серверного дедлайна.
- Пароли студентам, аккаунты и платёжные карты не нужны.
- Комнаты и голоса автоматически удаляются из Redis по TTL 24 часа; затем создайте новую игру.
- Не храните персональные/конфиденциальные данные студентов в качестве имён: достаточно имени и первой буквы фамилии.
- Звуки в браузерах доступны после первого нажатия пользователем; на панели проектора нажмите кнопку звука, если браузер блокирует воспроизведение.

## Структура файлов

- `public/index.html` — главная страница;
- `public/host.html` — пульт преподавателя (не показывайте его студентам);
- `public/screen.html` — синхронизированное табло для проектора;
- `public/play.html` — экран студента;
- `public/assets/` — интерфейсы, звук, таймер;
- `api/game.js` — логика серверной игры и голосования;
- `api/qr.js` — QR-коды, ведущие на ваш HTTPS-домен (самодостаточный генератор, без внешних сервисов);
- `lib/questions.js` — вопросы с ответами и объяснениями; доступен только серверу (не входит в `public/`, поэтому не скачивается из браузера);
- `lib/store.js` — общая постоянная база Upstash Redis;
- `lib/vendor-qr` — лицензированный локальный QR-генератор (Apache-2.0 с исходным компонентом MIT);
- `vercel.json` — настройки публикации (`outputDirectory: public`, заголовки, лимит функций);
- `local-server.js`, `tests.mjs` — локальное тестирование.
